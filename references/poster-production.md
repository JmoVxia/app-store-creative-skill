# 转换型与步骤型海报的生产方法

用于「多份输入 → 一个结果」「几个关键动作 → 一个结果」等宣传页。它补充[整套一致性](series-consistency.md)，不替代真实 App 截图的选题与证据要求，也不规定所有 App 都使用双栏或同一种配色。

目标是把审美选择转成能重复执行的母版和素材契约：先固定阅读关系、共享网格和槽位，再制作适配槽位的内容，最后用同一入口扩展。更多装饰、更多检查或更长提示词都不能代替这条生产路径。

## 1. 先给每页选对载体

在分镜里明确 `presentation`、`claim`、`evidence` 和 `input_scope`：

| 判断 | 采用的载体与约束 |
| --- | --- |
| 要让观众看到 App 的界面、工具或真实交互状态 | 使用真实 App 截图；需要机身时按设备合成规则制作 |
| 主体是输入内容、长结果或过程关系，而非 App 界面 | 可使用无设备框的海报；不能让内容看起来像被放进一个虚构的 App 页面 |
| 左侧只挑几段内容来说明乱序、相似或其他特征 | `input_scope: representative`；保存片段与源内容的映射，不宣称它们就是完整算法输入集合 |
| 声称左侧这些实际输入产生了右侧结果 | `input_scope: complete-evidence`；保存真实输入、产品处理入口和结果的对应证据，按实际功能验证 |

代表性宣传片段不需要强制覆盖全文、满足所有相邻重叠或重新跑算法；这会把视觉生产变成无关的算法搜索。真实输入结果的声称也不能借「只是海报」跳过证据。逐设备、本地化的实际 App 使用画面页数仍按主流程单独核算。

将一句宣传收益放在顶部。主体用内容关系证明它，短列名和短步骤名辅助识别；不再把操作说明段落、教程注释或重复结论塞到卡片下方。是否在图面标「示例」按用户用途决定，索引中的素材来源和合成性质始终如实记录。

## 2. 从整套标题向下建立一个网格

续作先测量已确认的后续页面：画布、背景、标题上沿、字号、行高、断行、副标题、标题区高度和主体起点。新海报使用相同标题组件；若用冻结的标题位图，逐语言、设备、页码保存原件与哈希，不能把整张旧图当作可编辑母版。背景可以在确认范围内调整，但顶部不能另起一套字体和层级。

同设备的关联海报先共享以下参数，不能分别为左右列或每页另算一套宽度：

```text
canvas_width, canvas_height
header_height, label_y, body_top, group_height
card_width, paper_padding, column_gap, group_x
paper_radius, paper_border, paper_shadow
badge_size, badge_inset, badge_radius, badge_font, badge_color
arrow_shaft, arrow_head_width, arrow_head_height, arrow_inset
```

双栏的直接计算关系：

```text
content_width = card_width - 2 × paper_padding
group_width   = 2 × card_width + column_gap
group_x       = (canvas_width - group_width) / 2
right_x       = group_x + card_width + column_gap
content_height = group_height - 2 × paper_padding
arrow_center_y = body_top + group_height / 2
```

左右外卡同宽，01与02的组宽也相同；列名在对应外卡上方居中。箭头置于两列之间，表示左侧情况变化为右侧结果，不能附着在某一步卡片上。短小、过细的箭头在商店缩略图中会失去连接作用；先在最终展示尺度验证线身、箭头面积及与阴影的层级关系。

下面是一套已完成双设备海报使用过的几何基准，可作为起点；换画布、内容密度、字体或品牌时重新确定，不能当成 Apple 要求：

| 参数，最终输出像素 | 手机竖版 | 平板竖版 |
| --- | ---: | ---: |
| 画布 | 1320 × 2868 | 2064 × 2752 |
| 标题区高度 / 主体起点 | 580 / 648 | 580 / 648 |
| 外卡宽 / 内容宽 | 580 / 532 | 684 / 636 |
| 共用内边距 | 24 | 24 |
| 栏距 / 整组宽 / 左坐标 | 64 / 1224 / 48 | 104 / 1472 / 296 |
| 整组高 / 右内容高 | 2156 / 2108 | 2056 / 2008 |
| 四张输入的单张视窗高 / 卡间距 | 467 / 32 | 439 / 36 |

该基准的纸卡圆角18、1px浅灰边、轻阴影，角标44×44、字号28、圆角8；角标统一在纸卡左上24px，直接压在片段保留的标号区，或进入步骤标题行。图面只保留数字，不重复写「截图」等无效字。实心连接箭头采用12px线身、22×34px箭头头部，两侧各留8px。颜色来自项目品牌，不要求所有项目采用红色。

先以纯色占位块校对两页网格。这个阶段就发现宽度、首尾、角标或箭头不一致时，修共享参数后再放真实内容。

## 3. 根据视窗制作内容，而不是靠缩放补救

每个素材槽记录 `asset_id`、`role`、`width/height`、`fit`、`language`、必须完整区域和允许裁区。母版、内容生成器与导出批次读取同一参数来源。不得只在素材索引中把尺寸改成目标尺寸；实际文件也必须匹配。

| 槽位 | 制作与放置方法 |
| --- | --- |
| 完整结果 | 先确保内容宽度和字号在商店尺度可读，再按等比适宽计算高度；不得通过非等比拉伸或裁末行凑齐外卡 |
| 代表性输入片段 | 从同源完整内容取有意义的连续片段，保留完整消息、编号和重要附件；固定视窗高，短差用同源底色补足，记录源ROI与补位区域 |
| 关键步骤 | 取与当前版本相符的原生引导图或已核实插图，保持整图比例；卡内空间围绕完整图形分配，不能裁掉主要按钮或弹窗 |
| 既有真实文档结果 | 使用用户的真实基线，先做最小脱敏，再取完整记录边界；保留原数字、汇总、字体和行距，避免重新排成看似真实的假结果 |

### 四片输入与完整长图

设输入数为 `N`、固定卡间距为 `g`，每片的目标内容高度可直接倒推：

```text
input_height = (group_height - (N - 1) × g) / N - 2 × paper_padding
```

若得不到整数或放不下完整消息，先调整内容取段、消息长度、附件尺寸或组高；不要给每片偷偷设置不同内距。输入顺序可以打乱，编号应与源片段身份一致。列名表达「乱序截图」「完整长图」即可，不要给图面增加片数承诺，除非数量本来就是要宣传的信息。

自编聊天先建立内容原型，不直接在最终海报里一张张拼气泡。使用一种可信的聊天基线：从实际参考图测背景、收发气泡、正文、时间、头像、行高和消息间距；记录采样区域，压缩图主色不能称作官方设计令牌。保持自然内容流与固定消息间隔，避免 `space-between` 把不同高度的消息硬撑满。

文字承担主要阅读，小照片、位置卡、文件卡等提供节奏。先以文字、图片及附件的面积比例检查是否某张照片压过所有内容；附件使用与气泡相近的底色和低饱和点缀，不能一个高亮地图标记或大色块抢走海报主视觉。相同类型复用同一个组件与间距。全图片、全文字、过大的照片和随意变化的卡片形式都应在首样前调整，而非等所有语言做完后补救。

### 三步与长结果

先固定三卡间距、共享卡宽、内边距、标题行高与图文间距。设每图等比适宽后的高度为 `h1/h2/h3`，共同的标题与内边距占用为 `b`：

```text
extra = group_height - 2 × step_gap - (h1 + h2 + h3) - 3 × b
card_height[i] = h[i] + b + extra / 3
```

`extra ≥ 0` 时把额外空间分配到三张图形区，使图形上下留白平衡；不把空白集中压给中间一张。若 `extra < 0`，先检查源图内是否有多余外白，再调整允许的整体图形比例或组高；完整控件约束优先。不要靠加入教程说明填空。

真实文档若比槽位长，按完整条目取景并记录裁区。不同设备可展示不同条目数，但必须保留原完整源；这不是允许随意删除汇总或改写金额。脱敏限定在已声明的公司名等ROI内，例如改为「XXX公司」，ROI外按原像素核对。不能为排版整齐重新生成全部文字。

## 4. 让网页控制几何，让位图提供内容

HTML/CSS负责文字、卡片、序号、箭头、对齐与语言变体；照片、插画等需要时由ImageGen提供独立冻结素材。不要让ImageGen直接画整张带文字、数字、原生UI或真实处理结果的海报。反复生成整张图片无法保证列宽、内距、语言和控件一致。

每组合可以使用同一模板加数据，也可以生成薄HTML入口，不能复制母版形成逐页分叉。生成入口至少完成：

1. 从一份配置读取设备网格、页面类型、文案和素材索引，解析出全部组合。
2. 检查路径、哈希、自然尺寸、必需素材和列宽等式，失败则不写PNG。
3. 渲染前等待图片解码与字体就绪，完成布局后给出可等待的就绪节点。
4. 给文字加 `data-asc-text`，必须完整的内容加 `data-asc-essential`；将共享组件预期矩形写入批次的 `components`。
5. 导出使用同一浏览器、viewport、DPR、locale、字体和光栅路径；只在明确受影响的组合出新候选，不改已确认PNG。

可从附带的可编辑母版开始。它只准备本节两种布局，不替代分镜、真实素材制作或审美判断：

```bash
node scripts/poster.mjs init /path/to/project
# 填写项目内poster.json的品牌、文案、素材相对路径，再准备一个新轮次。
node scripts/poster.mjs prepare /path/to/project poster.json --id round-001
node scripts/render.mjs /path/to/project work/round-001/render-batch.json
python3 scripts/audit_images.py /path/to/project work/round-001/audit-batch.json --report work/round-001/audit-report.json
```

`init`复制`poster.json`与`poster/master.html`，不覆盖已有项目文件。配置初始素材为空，不能直接出图；先替换示例标题，并按下面的槽位准备PNG。所附画布和配色只是前述几何基准，按项目已确认的规范修改。

| 配置位置 | 含义与填写方法 |
| --- | --- |
| `tokens` | 品牌色、纸卡内距/边/圆角/阴影、角标、箭头及文字字号；同系列共用 |
| `devices.<设备>` | `canvas`、`headerHeight`、`labelY`、`bodyTop`、`cardWidth`、`columnGap`、`groupHeight`、输入和步骤间距；左右坐标、内容宽和各卡高度由此推导 |
| `locales.<语言>.browserLocale` | 渲染浏览器语言，例如`zh-CN`；页面文字仍从此语言的`pages`填写。可用该语言的`fontFamily`覆盖共用字体，避免繁体、日韩等套用错误字形 |
| `pages.<页>.layout` | `conversion`使用`inputs`；`steps`使用三项`steps`；每页需两个`labels`及短标题`title`行数组、`subtitle` |
| `pages.<页>.devices.<设备>.result` | 项目相对PNG路径；内容比例必须等于`(cardWidth−2×paperPadding):(groupHeight−2×paperPadding)` |
| 同上`.inputs` | `[{"number":3,"asset":"materials/input-3.png"},…]`；序号唯一；每张实际PNG比例等于本节公式推导的输入视窗 |
| 同上`.steps` | 三项`[{"title":"短步骤名","asset":"materials/step.png"},…]`；先按内容宽等比计算图高，余高均分到每个图形区；放不下直接报错 |
| 同上`.headerImage`（可选） | 冻结顶部位图；比例等于`canvas宽:headerHeight`，提供后不渲染本页的`title/subtitle`。这里只是截图系列的顶部，不是App Store Header投放素材 |

`prepare`在任何PNG产生前检查缺失素材、项目外路径、符号链接越界、PNG天然尺寸比例、网格边界和顶部文字重叠。它从同一组计算结果生成HTML入口、完整`expected_outputs`、资源哈希和`components`；不会重新绘制图片中的原生UI或修补不适配的素材。可编辑唯一母版保留在`poster/master.html`，改后用新轮次重新准备；不要手改`work`里的生成页。

输出位于`candidates/<轮次>/<语言>/<设备>/<页>.png`，批次和几何/图片报告位于`work/<轮次>`。缺图、比例不符或步骤图过短而留下明显空白时，回到源素材和槽位设计，不把执行器成功说成审美已通过。PNG中原件内部的文字和边界仍要按第5、6节自审。字体、资源或环境有变化时，按[执行工具](tooling.md)冻结对应依赖并重放代表样张。整个项目可迁移到新目录，执行入口不依赖原项目的候选目录。

## 5. 先过一套首样，再批量

首样应同时检验两页之间的关系。先做主语言两页，并在内部检查平板和最长标题组合；用户指定先看一张时仅交指定张，其他内部检查不增加交付负担。看整张宣传的识别速度，再看原尺寸的字形、源图内部边距和风险局部。不要用占位稿通过审美后才第一次把真实内容放进去。

达到以下状态再锁母版：

- 一眼可读「左侧条件 → 右侧结果」，主体不依赖说明段落才能成立。
- 与后续页面的标题字体、基线和背景关系一致，主体达到相近的视觉分量。
- 同设备两页的左右卡宽、整体宽、内距、角标和连接位置一致；原件内部的留白也均衡。
- 所有重要内容平直、清楚、完整；旋转、弯曲、透视或叠压没有遮挡主内容。
- 已明确哪些是自编内容、真实App画面、真实结果或引导插图，以及它们的语言策略。

锁定记录包含母版、参数、素材、字体与环境指纹及用户实际确认范围。然后一次补齐语言×设备×页码矩阵，保留同一网格；英文变长优先改自然表达或断行，不能某页单独缩小到另一套字号。已确认主语言素材无需反复生成。

本地化有两层：宣传文字与位图内部文字。实际打开目标PNG检查引导图、弹窗、按钮等；目录叫繁体不代表其中已经是繁体。真实文档的原内容可有明确的跨语言复用例外，索引应区分 `ui_language`、`content_language` 和例外原因；不得用例外掩盖漏翻译的操作界面。

## 6. 用可观察的失败定位修哪一层

| 发现的偏差 | 回到哪一层修 | 复核范围 |
| --- | --- | --- |
| 左右或01/02宽度不同、角标不齐、连接弱或偏位 | 共用网格、角标或箭头组件 | 所有引用该设备参数的页 |
| 外卡内距相同，视觉仍紧贴边或空得明显 | 源图内部留白、取段或内容组件；先查位图，不先改外卡padding | 使用这份源的组合 |
| 照片过大、附件太艳、画面像教程或难读 | 内容原型、信息层级或分镜 | 相关内容与依赖页；重新看整张 |
| 文档像重画、金额不一致、脱敏伤到邻字 | 真实基线与局部脱敏处理 | 原源ROI、脱敏ROI外与相关输出 |
| 字体、断行或某语插图错误 | 文案表、字体映射、目标语言位图 | 该语言的受影响设备与页 |
| DOM正确但图片空白、边缘漏图或内容被裁 | 资源加载、比例、遮罩、最终像素映射 | 出错边界及引用同资源的组合 |
| 改一页后另一页或语言倒退 | 参数覆盖顺序、素材依赖或旁路模板 | 受影响依赖；不重新推翻无关已确认成果 |

一次修正一组有共同原因的问题，再运行该组必要检查。不要每轮全量重采、重跑算法或重复做全部审计，也不要用大量技术检查代替肉眼确认海报是否舒服、清楚。

最终必要检查由目标矩阵产生：文件齐全与页序、尺寸与PNG格式、资源指纹、共享几何、文字和图片边界、位图内部语言、实际内容及原图映射、整套缩略图与风险原尺寸。共用组件按共享范围比较；语言不同的正文不作整图相等要求。重复出图验证选择代表性风险组合与冻结环境，已经证明稳定后不为每次局部文案修改重复全量生产。

## 7. 定稿与清理是生产流程的最后一步

用户确认对应的具体候选后，将其与未变化的后续页合并到一个正式交付目录。逐语言、设备检查页数、01起连续排序与哈希，保留同版本的Header、搜索素材、审核附件等范围外资料。若用户只要变化页预览，交付预览只汇总变化页，正式定稿仍保留完整系列。

制作源必须能独立更新：相对路径、唯一配置与素材索引、可编辑内容源、冻结输入、导出入口、所需环境和最终输出清单。历史保护记录可保存旧指纹，但活动脚本不能继续强制读取即将删除的旧候选目录。先把有效依赖迁到最终制作源，核对哈希，并在隔离目录用这套源复现代表组合；再删除已确认废弃且没有活动引用的过程稿。不要删除基线、唯一源图、用户原件或其他版本交付证据。

若任务还要求上传商店，按明确版本、本地化、设备和页序回读处理状态及文件校验值；上传完成、技术检查、视觉检查、用户确认和审核通过分别记录，不能互相替代。最终留下能继续生产的入口，而不是只留一批扁平PNG或一篇复盘。
