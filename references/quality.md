# 分层验收

## 定义项目标准

启动时把通用底线与该 App 的视觉标准分开。各检查保存对象、范围、方法、阈值、实际结果和证据；建议／未运行／失败／通过／用户已确认使用不同状态。

| 层次 | 需要核对 |
| --- | --- |
| 规格与格式 | 目标位置、尺寸、方向、格式、位深、颜色空间、透明规则、数量与命名 |
| 内容 | 确认文案、缺字、错语言、术语、币种／日期／单位、金额或数据关系、隐私与使用依据 |
| 排版 | 字体、断行、字号下限、溢出、遮挡、边界、对齐、安全区和完整内容 |
| 视觉 | 缩略观看的重点与吸引力，原尺寸的清晰度、边缘、接缝和加工痕迹 |
| 真实关系 | 输入输出对应、真实处理完成、原生界面状态、对照同源同区域同倍率 |
| 整套 | 品牌、标题与组件规则一致；场景不重复失去意义；设备／语言差异有依据 |
| 复现 | 同一基准、配置、素材、字体与环境下重复生产；可变区和固定区分别检查 |

官方规则以当次规格快照为准，不把示例的某组像素值或文件格式套到所有位置。

## 代表样张与全量检查

前期全部语言／设备参与规划和测量；用户确认母版与风险代表样张后批量生产。素材样张和海报样张分别验证，并在整体组合中再看一次。没有通过样张的关键真实素材，不直接批量冒充定稿。

批量后每张进行实际视觉检查，辅助脚本核对可计算项。不能只看联系表就声称全部细节无误，也不能用 OCR 成功代替文字正确、无截断。自动检查负责暴露问题，不能代替用户的审美确认。

## 一致性判断

相同输入和环境的固定区域以像素一致为目标。可变文字、原生布局和真实采集差异使用明确区域／阈值；每个区域说明为什么允许变化。不得扩大排除区域来掩盖未解释漂移，也不能只排除整块主体后声称仅文字改变。

复现比较先检查画布、字体、DPR、浏览器／系统、色彩转换、资源加载、随机内容和动画，再决定是否是设计问题。文件 SHA 相同代表字节一致；像素相同不代表 PNG 元数据相同，二者分开报告。

真实功能结果需按其性质判断。比如普通观看无明显瑕疵与极度放大像素完美是不同标准，应在该项目确认，不把原项目阈值升级为通用规则。功能效果不能靠修图通过。

## 网页渲染检查

等待字体与图像完成，缺失资源直接报错；记录文本 DOM 边界、滚动溢出、computed 字体和 safe rect。DOM 指标只能覆盖可测量布局，不能完全证明字形无裁切或整体美观。所有时钟、随机数、排序、动图／视频帧和网络资源需在源层控制；渲染器关闭 CSS 动画并不等于所有动态内容冻结。

`render.mjs` 为本地 HTML 提供可替换的批量执行器；`audit_images.py` 检查格式和显式区域差异。报告会写入指定路径，图像审计不修改输入图片。使用前阅读 [工具说明](tooling.md)。

## 交付前

复核官方规格变化、输出清单、素材依赖、当前确认基准与待确认项。交付正式图和为后续修改所需的项目生产源；源码／素材保留在项目中，不上传通用技能仓库。

如只完成部分平台、语言或采集验证，明确范围；没有跨 App 实证就标待验证。App 编译、测试、真实采集、网页渲染、算法运行、静态图片检查和用户确认分别据实报告。

## 技能本身的验证

原项目回放检查方法是否吸收真实过程；同参数重复生产检查执行器；不同类型 App 的代表页闭环检查是否写死风格或条件。不额外制作另一 App 全套。记录本机实际结果和限制；另一个 App 尚未提供时保留 pending，不用合成演示替代跨 App 验证。
