# 分层验收

## 定义项目标准

启动时把通用底线与该 App 的视觉标准分开。各检查保存对象、范围、方法、阈值、实际结果和证据；建议／未运行／失败／通过／用户已确认使用不同状态。

| 层次 | 需要核对 |
| --- | --- |
| 规格与格式 | 目标位置、尺寸、方向、格式、位深、颜色空间、透明规则、数量与命名 |
| 内容 | 确认文案、缺字、错语言、术语、币种／日期／单位、金额或数据关系、隐私与使用依据 |
| 排版 | 字体、断行、字号下限、溢出、遮挡、边界、对齐、安全区和完整内容 |
| 视觉 | 缩略观看的重点与吸引力，原尺寸的清晰度、边缘、接缝和加工痕迹 |
| 真实关系 | 输入输出对应、真实处理完成、原生界面状态、对照同源同区域同倍率 |
| 整套 | 品牌、标题与组件规则一致；场景不重复失去意义；设备／语言差异有依据 |
| 复现 | 同一基准、配置、素材、字体与环境下重复生产；可变区和固定区分别检查 |

官方规则以当次规格快照为准，不把示例的某组像素值或文件格式套到所有位置。

## 从首样到最终 PNG

首轮就选能暴露真实操作、图文密度或设备差异的代表场景。先验原始素材是否包含承诺的功能状态，再按实际商店尺寸导出一张，检查关键控件、结果和文案能否在整张里同时读清。[整套一致性规范](series-consistency.md)中的组件、间距和边界检查适用于首样；平板、最长文案、弹层及高风险四角在相关规则冻结前验证，不等批量后才看。用户确认此样张后再扩展同规则组合。已有素材可先出样，缺原生画面的设备继续备料并保留待验状态。

对最后一次导出的 PNG 逐张解码，核对交付矩阵中的语言、设备、页序、尺寸、方向、位深、颜色和透明规则，找出缺失、多余或意外重复的图。按约定分别查渲染时的色彩空间、PNG 色彩标记及嵌入 ICC；要求原样复用的文件另核字节哈希。随后分三种尺度查看：

| 查看尺度 | 检查并回到相应制作环节 |
| --- | --- |
| 商店缩略总览 | 并排看标题基线、设备框、阴影、卡间距和内容密度。从画面指出各页的主要操作或结果，用最终页序按设备和本地化复算[实际使用图数量](localization-specs.md)。不足则换入真实使用场景；多页共同漂移修网页母版，个别页面失衡只调该页。 |
| 每张原始尺寸 | 逐张核对字形、断行、语言、导航与工具选中态，检查主结果是否被浮层遮住。用原生截图或真实输入输出核对当前版本；换错状态、平台或语言就回 App 重采，单页图文比例偏差回内容源或槽位调整。 |
| 风险局部放大 | 每张检查屏幕四角和四边：内容不得冒出机身，圆角不得漏底；另看半透明边缘、旧框／旧岛残影、按钮被裁、切片边界、箭头落点。前后对照要能在同源、同点、同倍率下看清变化。边缘残留修裁切／遮罩层，结果不明显则换取样或输入。重新导出受影响的 PNG，并取一张使用相同组件的对照页回看。 |

OCR、DOM 测量和格式脚本辅助定位。缺字、误译、虚假操作和不当裁切仍要用最终图与相应原件核实。交付时分别列明哪些组已完整检查、哪些只有代表样张、哪些属于流程示意。

## 一致性判断

相同输入和环境的固定区域以像素一致为目标。可变文字、原生布局和真实采集差异使用明确区域／阈值；每个区域说明为什么允许变化。不得扩大排除区域来掩盖未解释漂移，也不能只排除整块主体后声称仅文字改变。

按层选择检查对象，不能用整个设备矩形代替实际选区：

| 对象 | 首样与批量的检查方式 |
| --- | --- |
| 输出矩阵 | 从目标语言×设备×页序生成预期清单，与渲染任务、成品目录三方核对；缺失、多余和意外重复分别报告。共享同图的本地化须有明确依据。 |
| 机身／固定组件 | 对同设备固定资源及不透明内部区域核哈希／比像素；透明混合边界单列。官方机身图不额外添加阴影，其他自有组件按其规范检查。 |
| 四角／四边 | 用独立于最终成图、来自原件透明轮廓与屏幕开口的掩码确定机身外部，在最终 PNG 与声明背景比较；每角每边均记录实际覆盖像素，不允许空选区通过。复杂背景用独立背景图比较。 |
| 屏幕与内容 | DOM 核对槽位、内边距和 computed 样式；最终 PNG 再与原件按声明的等比变换检查，另核四侧边带，防止靠裁切、拉伸或补白通过。 |
| 状态栏与标题 | 同设备、同语言、同状态分别比对；弹层变暗单独分组或按已记录变换检查。硬件不随弹层变暗。标题核坐标、基线、字重、字号、断行与字形边界。 |

掩码需明确以 alpha 还是亮度解释，冻结来源及哈希，并查看选区是否覆盖要检查的实物。不要从可能已经错误的成品反推一个避开错误的掩码。抗锯齿边界如需内缩，先在项目标准声明宽度、原因和边界补查方式；不能把本项目的像素数或色阶容差写成通用默认。`audit_images.py` 可执行矩阵、冻结资源、带掩码区域比较及背景外溢检查，配置见[工具说明](tooling.md)。

外部零外溢与内部有正确内容必须同时成立：CSS 遮罩加载失败可能使整块屏幕透明，单查机身外部仍会通过。首样和批量均核对可见屏内与原件的对应，不能把全空、错源或仅剩机身的图片当作边界检查成功。

等尺寸的锁定图层直接比像素，按约定缩放的标题可比字面边界与墨迹重叠。不同光栅器重采样造成的内容误差与固定组件漂移分开；阈值及理由由项目记录，不统一放宽。原生工作区与自编图文内容的留白也分开归因，发现源内容内部间距不同须报告范围，不能概称“所有留白一致”。

复现比较先检查画布、字体、DPR、浏览器／系统、色彩转换、资源加载、随机内容和动画，再决定是否是设计问题。文件 SHA 相同代表字节一致；像素相同不代表 PNG 元数据相同，二者分开报告。

真实功能结果需按其性质判断。比如普通观看无明显瑕疵与极度放大像素完美是不同标准，应在该项目确认，不把原项目阈值升级为通用规则。功能效果不能靠修图通过。

## 网页渲染检查

等待字体与图像完成，缺失资源直接报错；记录文本 DOM 边界、滚动溢出、computed 字体和 safe rect。启用组件契约时还核对屏幕矩形、padding、圆角、遮罩模式和图片原生比例，在写出该 PNG 前拦截偏差。灰度图片在 alpha 遮罩模式下可能完全不裁角，即使 DOM 矩形正确仍会漏图；因此 computed 模式与最终角部像素都要检查。DOM 指标只能覆盖可测量布局，不能完全证明字形无裁切或整体美观。所有时钟、随机数、排序、动图／视频帧和网络资源需在源层控制；渲染器关闭 CSS 动画并不等于所有动态内容冻结。

`render.mjs` 为本地 HTML 提供可替换的批量执行器；`audit_images.py` 检查格式和显式区域差异。报告会写入指定路径，图像审计不修改输入图片。使用前阅读 [工具说明](tooling.md)。

## 交付前

复核官方规格变化、输出清单、素材依赖、当前确认基准与待确认项。交付正式图和为后续修改所需的项目生产源；源码／素材保留在项目中，不上传通用技能仓库。

仅在另获授权发布或替换商店素材时，上传后从 App Store Connect 回读目标设备槽位、数量、展示顺序、文件校验值和处理状态，清点旧图及重试副本。分别记录本地 PNG 验收、商店接收、重新提交和 Apple 审核决定。

如只完成部分平台、语言或采集验证，明确范围；没有跨 App 实证就标待验证。App 编译、测试、真实采集、网页渲染、算法运行、静态图片检查和用户确认分别据实报告。

## 技能本身的验证

原项目回放检查方法是否吸收真实过程；同参数重复生产检查执行器；不同类型 App 的代表页闭环检查是否写死风格或条件。不额外制作另一 App 全套。记录本机实际结果和限制；另一个 App 尚未提供时保留 pending，不用合成演示替代跨 App 验证。
