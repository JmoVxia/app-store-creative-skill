# 维护与迁移

## 保存每轮而非重写历史

确认的状态进入基准；候选修改在当前工作状态和新轮次内进行。保留原目标、具体偏差、保留项、修改范围、影响、示意哈希、用户回复及否决原因。重要否决示意属于决策证据，不能只记“太丑”而丢失原因。

不把“用户喜欢一个方向”解释为所有细节已确认。用户简短回复可以作为本轮确认，但其指向必须清楚；存在多个未决问题时先澄清范围。

## 接入已有成果

盘点规范、源文件、素材、成图及确认记录，核对版本关系。可以复用已合格部分，只补缺口；只有成图时记录不可还原的部分，不能假定拥有可编辑层或真实功能证据。

## 变更与失效

先找变更类型，再沿依赖处理：

| 变更 | 优先检查 |
| --- | --- |
| 文案／新增语言 | 字体支持、占位、断行、素材正文、原生语言状态、压力样张 |
| 换照片／素材 | 比例、焦点、完整边界、配色、清晰度、取景、真实性 |
| 功能／App UI 更新 | 受影响页面、采集原件、术语、功能证据与宣传边界 |
| 公共参数更新 | 使用该参数的页面、语言、设备及组合效果 |
| 设备／商店位置新增 | 原生布局、规格、独立构图、裁切、素材长度 |
| 浏览器／系统／字体更新 | 环境差异、代表图回放，先排查执行变化 |
| 技能更新 | 契约与方法变化、迁移影响、项目明确采用的版本 |

在已确认范围内联动适配；超出范围先说明关联影响，分轮出示意再确认。只修改受影响结果，不因局部问题推翻整套。

## 用户手改

把用户修改落实回生产源并对照复现；无法还原的部分作为明确的冻结素材维护。下一次生产前核对新原件，不能覆盖用户改动或只更新最终 PNG。新增素材必须更新索引和哈希。

## 换会话续做

读取状态、基准和未完成轮次，核对依赖文件及实际运行状态。明确现在做到了哪一步、哪些已经确认、下一步是什么。状态与文件不一致时先定位，不重复采集合格素材，也不从历史消息猜当前模拟器画面。

## 分层保留

当前生产入口只展示有效基准和当前候选。历史已确认版本、确认／关键否决图、必要源、真实输入输出、脚本和原件哈希保留可恢复版本。停用稿归档，不混入交付；可再生缓存和未被引用的临时文件可按项目规则清理。

清理前检查当前与历史基准、轮次、素材派生链、模板、语言／设备变体及项目脚本引用。对无法自动解析的 HTML/CSS/脚本引用标记需核查，不能假装依赖图完整。不可恢复删除要获得明确确认；技能工具本身不提供 purge。

确认文件从一开始使用带轮次或版本的稳定位置，例如 `sources/round-001/`、`candidates/round-001/`，下一轮另建版本，不原地改写已确认引用。归档优先改变索引中的状态和当前展示入口；物理搬动被引用原件前，必须保留可解析的原位置或完成明确的定位迁移并核对全部引用。快照工具只保存状态和哈希，不会替代素材备份。

## 公开技能升级

项目经验先区分通用问题与 App 专属选择。只有真实证据支持的通用改进才进入技能候选，保留兼容影响及验证结果；不在生产用户项目时自动修改已安装技能。私有素材、数据、路径和凭证不得随经验上传。

项目固定技能版本，旧版本保留回放能力，升级不自动发生。schema_version 变化需有明确转换及回退方案；首版工具对未知契约版本拒绝写入，不猜测迁移。发布更新前说明验证过的环境／平台和未验证项。
